## Achados

### [P2] README com numeração de passos duplicada — alteração não commitada

A árvore de trabalho **não está limpa**: há uma modificação em `README.md` **feita depois do commit `a1f7dd4`**, que reescreveu a numeração da lista "Configurando conexão com o AionCore local": os passos **"4. Inicie `npm run build…`"** e **"5. Na interface, acesse Configurações…"** passaram a ser **"1."** e **"2."**, logo após os itens 1, 2 e 3. O resultado lido do arquivo é uma lista 1, 2, 3, **1, 2** — emGitHub a segunda lista é renderizada como lista própria, reiniciando em 1, e o leitor perde a ordem dos passos de configuração.

O estado **commitado** (`a1f7dd4`) está correto (4. e 5.); a regressão está apenas na árvore local, provavelmente de um formatador Markdown que reinicia a numeração da segunda lista após a linha em branco inserida. O risco é concreto: o próximo `git commit -a` versionaria a documentação quebrada, e a afirmação "árvore de trabalho limpa" do relatório não corresponde mais ao estado real.

Correção necessária: desfazer a renumeração (mantendo 4. e 5., ou evitando a quebra da lista) e commitar. Recomendo também passar a conferir `git status` **depois** da última edição de documentação, e não antes.

### [P3] `controlToken` protegido por `mode: 0o600`, sem efeito prático no Windows

`vertice-ctl.mjs:522-524` grava `.vertice/server.json` com `mode: 0o600`. Em Windows, esse modo é **advisory**: o Node não restringe a ACL e o arquivo herda as permissões do perfil do usuário. O `controlToken` — que autoriza `/__vertice_ctl/shutdown` e a leitura de `/__vertice_ctl/identity` — fica, portanto, legível por qualquer processo local executado como o mesmo usuário.

O impacto é baixo para a v1 local (o endpoint de controle exige o token e só encerra a própria instância verificada; o `doctor` não expõe o valor — confirmei), mas o selo **"somente loopback + token de controle"** não é completo no Windows sem ACL explícita. Recomendo registrar o item para o V6-09/V6-10: aplicar ACL restritiva no Windows (`icacls`) ou mover o segredo para o Credential Manager/DPAPI, mantendo o arquivo apenas com metadados não sensíveis.
